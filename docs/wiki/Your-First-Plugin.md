# Your first plugin

In this page you write a plugin of your own, outside the repository of Nebula, with two components: a clock that shows
the time, and a window that shows a widget. You build it against an installed Nebula, assemble the two in NebulaStudio,
and run them. The code below is complete: copy it as it is.

## What you need

- **A Nebula to build against**: the unzipped zip of a [release](https://github.com/Shuko83/Nebula/releases), or
  `<build>/package`, which a build of Nebula stages. See [getting started](Getting-Started.md).
- **The same Qt and compiler as that Nebula**, whose name tells them: `Nebula_3.0.0_win-x64_msvc2022_Qt6.12` is built
  with Visual Studio 2022 and Qt 6.12. A plugin built with another Qt, or another compiler, is not one that Nebula can
  load.
- **CMake 3.21** or later.

## The project

```text
Acme/
├── CMakeLists.txt
└── TimePlugin/
    ├── CMakeLists.txt
    └── src/
        ├── ClockComponent.h
        ├── ClockComponent.cpp
        ├── WindowComponent.h
        └── WindowComponent.cpp
```

`Acme/CMakeLists.txt` finds Nebula, which brings `nebula_add_plugin()` and the CMakeUtils it relies on:

```cmake
cmake_minimum_required(VERSION 3.21)
project(Acme VERSION 1.0.0 LANGUAGES CXX)

set(cmu_organization "AcmeCorp") # First part of the plugin ids: AcmeCorp.Acme.TimePlugin

find_package(Nebula 3.0 REQUIRED COMPONENTS Core)
find_package(Qt6 REQUIRED COMPONENTS Widgets)

# Executables and plugins side by side: <build>/bin, and <build>/bin/plugins.
set(CMAKE_RUNTIME_OUTPUT_DIRECTORY "${CMAKE_BINARY_DIR}/bin")

add_subdirectory(TimePlugin)
```

`cmu_organization`, set before `find_package`, starts the id of each plugin: here, `AcmeCorp.Acme.TimePlugin`, the
organization, the name of the project, then the name of the plugin, which take letters, digits, `_` and `-` only.

`Acme/TimePlugin/CMakeLists.txt` declares the plugin:

```cmake
nebula_add_plugin(
    NAME TimePlugin
    DESCRIPTION "A clock, and a window to show it"
    LINK_LIBRARIES PRIVATE Qt6::Widgets
)
```

Its sources are the files of `src/`, found by themselves: there is nothing to list. `nebula_add_plugin()` also writes
the class of the plugin, `TimePlugin` in `TimePlugin.h`, in the build directory: its components register in it, and
you write nothing else.

## A component that provides an interface

`ClockComponent` shows the time in a label, and provides that label to whoever wants to show it, as `display`, a
`QWidget`. Its `format` is a property, set in NebulaStudio and saved with the project. It refreshes the time every
second, but only while it runs.

```cpp
// TimePlugin/src/ClockComponent.h
#pragma once

#include <QLabel>
#include <QString>
#include <QTimer>

#include "Nebula/Component/Component.h"

// Shows the time in a label it provides as "display", refreshed every second while it runs.
class ClockComponent : public Nebula::Component
{
    Q_OBJECT
    Q_CLASSINFO("description", "Shows the time, refreshed while it runs")
    Q_CLASSINFO("category", "Time")
    Q_PROPERTY(QString format READ format WRITE setFormat NOTIFY formatChanged)

  public:
    ClockComponent();

    [[nodiscard]] QString format() const;
    void setFormat(const QString& format);

  signals:
    void formatChanged(const QString& format);

  protected:
    bool onStart() override;
    void onStop() override;

  private:
    void showTime();

    QLabel m_display;
    QTimer m_timer;
    QString m_format = QStringLiteral("hh:mm:ss");
};
```

```cpp
// TimePlugin/src/ClockComponent.cpp
#include "ClockComponent.h"

#include <QTime>

#include "TimePlugin.h" // The class of the plugin, generated by nebula_add_plugin(NAME TimePlugin)

NEBULA_REGISTER_COMPONENT(TimePlugin, ClockComponent);

ClockComponent::ClockComponent()
{
    m_display.setAlignment(Qt::AlignCenter);
    showTime();
    m_timer.setInterval(1000);
    connect(&m_timer, &QTimer::timeout, this, &ClockComponent::showTime);
    provideInterface<QWidget>(QStringLiteral("display"), &m_display); // Available at once
}

QString ClockComponent::format() const
{
    return m_format;
}

void ClockComponent::setFormat(const QString& format)
{
    if(m_format == format)
    {
        return;
    }
    m_format = format;
    showTime();
    emit formatChanged(m_format);
}

bool ClockComponent::onStart()
{
    showTime();
    m_timer.start();
    return true;
}

void ClockComponent::onStop()
{
    m_timer.stop();
}

void ClockComponent::showTime()
{
    m_display.setText(QTime::currentTime().toString(m_format));
}
```

What to notice:

- It derives publicly from `Nebula::Component`, has `Q_OBJECT` and a default constructor: the plugin creates it.
- `NEBULA_REGISTER_COMPONENT(TimePlugin, ClockComponent)` registers it in the class of its plugin, as the plugin
  loads.
- Its objects, the label and the timer, are members, created with it and destroyed with it.
- `provideInterface<QWidget>(name, pointer)` provides the label as a `QWidget`: that type is what a consumer has to
  ask for. Given in the constructor, the pointer is available at once.
- `onStart()` and `onStop()` are called as the application starts and stops. Returning `false` from `onStart()` would
  refuse to start.
- Its setter changes the value only when it differs, then emits its `NOTIFY` signal: NebulaStudio follows it, and
  settings files do too.

## A component that consumes one

`WindowComponent` is a window that shows the widget it is given as `content`, which it cannot do without, while it runs.

```cpp
// TimePlugin/src/WindowComponent.h
#pragma once

#include <QMainWindow>
#include <QString>

#include "Nebula/Component/Component.h"

// A window showing the widget it consumes as "content", which it cannot do without, while it runs.
class WindowComponent : public Nebula::Component
{
    Q_OBJECT
    Q_CLASSINFO("description", "A window showing a widget while it runs")
    Q_CLASSINFO("category", "Time")
    Q_PROPERTY(QString title READ title WRITE setTitle NOTIFY titleChanged)

  public:
    WindowComponent();

    [[nodiscard]] QString title() const;
    void setTitle(const QString& title);

  signals:
    void titleChanged(const QString& title);

  protected:
    bool onStart() override;
    void onStop() override;

  private:
    void showContent();
    void giveBackContent();

    QMainWindow m_window;
    QWidget* m_content = nullptr; // Consumed: written by Nebula
};
```

```cpp
// TimePlugin/src/WindowComponent.cpp
#include "WindowComponent.h"

#include "TimePlugin.h"

NEBULA_REGISTER_COMPONENT(TimePlugin, WindowComponent);

WindowComponent::WindowComponent()
{
    m_window.setWindowTitle(QStringLiteral("Clock"));
    consumeInterface<QWidget>(
        QStringLiteral("content"), m_content, Nebula::InterfaceRequirement::Mandatory,
        [this] { showContent(); },      // m_content is set
        [this] { giveBackContent(); }); // m_content is about to be set back to nullptr
}

QString WindowComponent::title() const
{
    return m_window.windowTitle();
}

void WindowComponent::setTitle(const QString& title)
{
    if(m_window.windowTitle() == title)
    {
        return;
    }
    m_window.setWindowTitle(title);
    emit titleChanged(title);
}

bool WindowComponent::onStart()
{
    m_window.show();
    return true;
}

void WindowComponent::onStop()
{
    m_window.hide();
}

void WindowComponent::showContent()
{
    m_window.setCentralWidget(m_content);
    m_content->show(); // Hidden when it was taken from another window
}

void WindowComponent::giveBackContent()
{
    m_window.takeCentralWidget();
    m_content->setParent(nullptr); // It belongs to the component that provides it: the window would delete it
}
```

What to notice:

- `consumeInterface<QWidget>(name, member, requirement, onAvailable, onUnavailable)` declares the interface; Nebula
  writes the member. It stays `nullptr` until the interface is bound to one another instance provides, and that one is
  available.
- `Mandatory` tells NebulaStudio to mark the instance until the interface is bound. Nothing else checks it.
- `onUnavailable` is called while the member still points to the widget: the window lets it go then, and gives it back
  without a parent. Kept as a child, the window would delete it with itself, while it is a member of the clock.

## Build it

From the folder that holds `Acme`, with the paths of your Nebula and of your Qt:

```bash
cmake -S Acme -B Acme/build "-DCMAKE_PREFIX_PATH=C:/Nebula_3.0.0_win-x64_msvc2022_Qt6.12;C:/Qt/6.12.0/msvc2022_64"
```

```bash
cmake --build Acme/build --config Release
```

The plugin is `Acme/build/bin/Release/plugins/TimePlugin.nbdl`. Build it in the configuration of your Nebula, `Release`
for the zip of a release: Qt does not load a `Debug` plugin in a `Release` application, nor the other way round.

## Assemble and run it

1. **Have NebulaStudio list it.** Start NebulaStudio with the folder of the plugin:

   ```bash
   NebulaStudio --plugin-dir C:/work/Acme/build/bin/Release/plugins
   ```

   then, in its **Plugins** tab, select `TimePlugin` and click **Load**: NebulaStudio lists the plugins it finds, but
   loads only those it needs. Or, NebulaStudio already open, use **Open plugin...** in that tab and choose
   `TimePlugin.nbdl`, which loads it at once. The **Components** tab now lists `ClockComponent` and
   `WindowComponent`, in the category Time; hovering one shows its description.
2. **Place them.** Drag both into the edition zone: `ClockComponent1` and `WindowComponent1`. The window shows an
   amber mark, and the list of problems tells that its `content` is bound to nothing.
3. **Link them.** Drag from the `display` dot of `ClockComponent1`, on its right, to the `content` dot of
   `WindowComponent1`, on its left. The mark goes.
4. **Set them.** Select `WindowComponent1` and give its `title` a value of your own; select `ClockComponent1` and try
   `hh:mm` as its `format`.
5. **Run them.** **Run** > **Start** (F5): the window opens, the time in it. **Run** > **Stop** (Shift+F5) closes it.
6. **Save them.** **File** > **Save As...**, `Clock.nbp`. The project names the components by their id,
   `AcmeCorp.Acme.TimePlugin.ClockComponent`, and the plugin by its id and its file.

## Change it

While NebulaStudio has the plugin loaded, its file stays in use, until NebulaStudio is closed: close NebulaStudio
before building the plugin again, or the link fails to write it. A plugin loaded again in the same NebulaStudio is the
one it read first.

When you move to another version of Nebula, build the plugin again against it: Nebula only checks that a plugin was
built against the same major version, but the classes a component derives from can change with a minor one, and a
plugin built against the former ones then crashes as soon as one of its components is created.

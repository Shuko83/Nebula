# Lesson 7 · Ship an application

*[The course](Course.md) › Lesson 7*

What you assembled in NebulaStudio is a project file; your users want an executable, which they start without
NebulaStudio. This lesson turns the alarm clock of lessons 5 and 6 into `Clock.exe`, and makes the folder you give them.

**You learn to** write the `main` of an application whose content is a galaxy, have CMake put next to it what it needs,
and make the folder to ship.

## What you need to know

- `Nebula::NebulaApplication`, of `Nebula::Application`, loads a galaxy as it is built and runs it with `exec()`.
- It finds its plugins in `plugins/` next to the executable, and its galaxy in `scene/`.
- `find_package(Nebula 3.0 REQUIRED COMPONENTS ... StandardPlugin)` gives the file of `StandardPlugin`, as the target
  `Nebula::StandardPlugin`.

[Running an application](Running-an-Application.md) and [deploying an application](Deploying-an-Application.md) tell
the rest.

## Exercise 7.1 · The alarm clock

**Goal**: a galaxy `AlarmClock.nbp`, made in NebulaStudio: a clock in the `Large` style and an alarm, in a panel, in a
window titled `Alarm clock`, the alarm on a fixed time for now, and a log bound to both.

**Do**: assemble it in NebulaStudio, and save it as `AlarmClock.nbp` in a new folder `Acme/Clock/`.

**Check**: **Start**: the time, large, above `Ringing!`.

| `Fixed1` | `FixedTimeComponent` | |
| `Alarm1` | `AlarmComponent` | |
| `Panel1` | `PanelComponent` | |

| From (provides) | To (consumes) |

## Exercise 7.2 · Clock.exe

**Goal**: an executable `Clock` that runs `AlarmClock.nbp`, with its name and its version, in the `Acme` project.

**Do**: write `Acme/Clock/src/main.cpp` and `Acme/Clock/CMakeLists.txt`, and add the folder to the project. The
executable needs, next to it, the DLLs of Nebula, `TimePlugin.nbdl` and `StandardPlugin.nbdl` in `plugins/`, and the
galaxy in `scene/`.

**Check**: `Acme/build/bin/Release/Clock.exe --console` opens the alarm clock, and the terminal shows
`log: Alarm1: Ringing at 07:30`.

<details>
<summary>Hint</summary>

[Running an application](Running-an-Application.md) has the `main` and the `CMakeLists.txt` of a `Clock`: add to its
post-build command the copy of `$<TARGET_FILE:Nebula::StandardPlugin>` into `plugins/`.

</details>

<details>
<summary>Solution</summary>

```cmake
# Acme/CMakeLists.txt
find_package(Nebula 3.0 REQUIRED COMPONENTS Core Application Standard StandardPlugin)
# ...
add_subdirectory(TimePlugin)
add_subdirectory(Clock)
```

```cpp
// Acme/Clock/src/main.cpp
#include <QCommandLineParser>

#include "Clock_info.h" // Generated by CMakeUtils for the executable Clock
#include "Nebula/Application/NebulaApplication.h"

int main(int argc, char* argv[])
{
    QCommandLineParser parser;
    Nebula::NebulaApplication app(argc, argv, parser, QStringLiteral("AlarmClock.nbp"),
                                  {.executable = {.name = QString::fromUtf8(ClockInfo::name),
                                                  .version = QString::fromUtf8(ClockInfo::version),
                                                  .organization = QString::fromUtf8(ClockInfo::organization)}});
    return app.exec();
}
```

```cmake
# Acme/Clock/CMakeLists.txt
cmu_add_executable(
    NAME Clock
    LINK_LIBRARIES PRIVATE Nebula::Application Qt6::Widgets
)

# Next to Clock.exe: the DLLs of Nebula, StandardPlugin in plugins/, and its galaxy in scene/.
add_custom_command(TARGET Clock POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E copy_if_different $<TARGET_RUNTIME_DLLS:Clock> $<TARGET_FILE_DIR:Clock>
    COMMAND ${CMAKE_COMMAND} -E make_directory $<TARGET_FILE_DIR:Clock>/plugins
    COMMAND ${CMAKE_COMMAND} -E copy_if_different $<TARGET_FILE:Nebula::StandardPlugin> $<TARGET_FILE_DIR:Clock>/plugins
    COMMAND ${CMAKE_COMMAND} -E copy_if_different ${CMAKE_CURRENT_SOURCE_DIR}/AlarmClock.nbp
            $<TARGET_FILE_DIR:Clock>/scene/AlarmClock.nbp
    COMMAND_EXPAND_LISTS)
add_dependencies(Clock TimePlugin) # The application loads the plugin without linking it
```

`TimePlugin.nbdl` is in `plugins/` already: `nebula_add_plugin()` writes it there.

</details>

## Exercise 7.3 · The folder to ship

**Goal**: a folder with all that `Clock.exe` needs, and nothing else, made by `cmake --install`.

**Do**: add install rules of a component `Clock` to `Acme/Clock/CMakeLists.txt`, install it to `dist/Clock`, and run it
from a terminal whose `PATH` has neither Qt nor Visual Studio.

**Check**: `dist/Clock` has `Clock.exe`, the DLLs of Nebula, of Qt and of the compiler, `plugins/` with
`TimePlugin.nbdl` and `StandardPlugin.nbdl`, and `scene/AlarmClock.nbp`; started from there, it rings.

<details>
<summary>Solution</summary>

```cmake
# The folder to ship: cmake --install <build> --config Release --component Clock --prefix <folder>
install(PROGRAMS $<TARGET_FILE:Clock> $<TARGET_FILE:Nebula::Core> $<TARGET_FILE:Nebula::Application>
    DESTINATION . COMPONENT Clock EXCLUDE_FROM_ALL)
install(FILES $<TARGET_FILE:TimePlugin> $<TARGET_FILE:Nebula::StandardPlugin>
    DESTINATION plugins COMPONENT Clock EXCLUDE_FROM_ALL)
install(FILES AlarmClock.nbp DESTINATION scene COMPONENT Clock EXCLUDE_FROM_ALL)
set(CMAKE_INSTALL_SYSTEM_RUNTIME_LIBS_SKIP ON)
include(InstallRequiredSystemLibraries)
install(PROGRAMS ${CMAKE_INSTALL_SYSTEM_RUNTIME_LIBS} DESTINATION . COMPONENT Clock EXCLUDE_FROM_ALL)
install(CODE "
    execute_process(COMMAND \"$<TARGET_FILE:Qt6::windeployqt>\" --no-compiler-runtime --no-translations
        \"\${CMAKE_INSTALL_PREFIX}/$<TARGET_FILE_NAME:Clock>\" COMMAND_ERROR_IS_FATAL ANY)
" COMPONENT Clock EXCLUDE_FROM_ALL)
```

```bash
cmake --install Acme/build --config Release --component Clock --prefix dist/Clock
```

</details>

## Questions

<details>
<summary>1. You forget StandardPlugin.nbdl. What does Clock.exe do?</summary>

It ends at once: its galaxy cannot be loaded, a plugin it needs being nowhere. `--console` says so, and
`exec()` returns `NebulaApplication::LoadFailed`, 1.

</details>

<details>
<summary>2. Where does a settings file of the alarm clock go, its directory left empty?</summary>

To the configuration directory of `Clock`, under `%LOCALAPPDATA%`, named after the organization and the name the
executable gives itself: that is why `main` sets them, and why they should not change after the first release.

</details>

<details>
<summary>3. Why give windeployqt Clock.exe only once the DLLs of Nebula are installed?</summary>

`windeployqt` copies the Qt that a binary and the DLLs next to it need: `Clock.exe` itself needs little of Qt, while
`Application.dll` needs Qt Widgets.

</details>

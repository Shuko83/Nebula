# Running an application

A project file is an application: its instances, set and bound, only have to be loaded and started. This page makes
`Clock.exe`, the executable that runs the `Clock.nbp` assembled in [your first plugin](Your-First-Plugin.md). The code
below is complete, and builds against the zip of a release as the plugin does.

## The main

`Nebula::NebulaApplication`, of the `Nebula::Application` library, is the `QApplication` of an executable whose content
is a galaxy: it loads it as it is built, and runs it with `exec()`.

```cpp
// Clock/src/main.cpp
#include <QCommandLineParser>

#include "Nebula/Application/NebulaApplication.h"

int main(int argc, char* argv[])
{
    QCommandLineParser parser;
    Nebula::NebulaApplication app(argc, argv, parser, QStringLiteral("Clock.nbp"));
    return app.exec();
}
```

As it is built, it reads the command line, finds the plugins of `plugins/` next to the executable, then opens
`Clock.nbp`, looked for in `scene/` next to it: its plugins are loaded, its instances created, set and bound. `exec()`
starts it, runs until the application quits, once its last window is closed, then stops it, which writes its settings
files.

## The CMake

Next to `TimePlugin`, in the `Acme` project of [your first plugin](Your-First-Plugin.md):

```text
Acme/
├── CMakeLists.txt
├── TimePlugin/
└── Clock/
    ├── CMakeLists.txt
    ├── Clock.nbp        the project saved by NebulaStudio
    └── src/main.cpp
```

In `Acme/CMakeLists.txt`, ask for `Application` too, and add the folder:

```cmake
find_package(Nebula 3.0 REQUIRED COMPONENTS Core Application)
# ...
add_subdirectory(TimePlugin)
add_subdirectory(Clock)
```

`Acme/Clock/CMakeLists.txt`:

```cmake
cmu_add_executable(
    NAME Clock
    # Qt6::Widgets named here too: windeployqt only runs for an executable it sees linking Qt.
    LINK_LIBRARIES PRIVATE Nebula::Application Qt6::Widgets
)

# Core.dll and Application.dll next to Clock.exe, and its galaxy in scene/.
add_custom_command(TARGET Clock POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E copy_if_different $<TARGET_RUNTIME_DLLS:Clock> $<TARGET_FILE_DIR:Clock>
    COMMAND ${CMAKE_COMMAND} -E copy_if_different ${CMAKE_CURRENT_SOURCE_DIR}/Clock.nbp
            $<TARGET_FILE_DIR:Clock>/scene/Clock.nbp
    COMMAND_EXPAND_LISTS)
add_dependencies(Clock TimePlugin) # The application loads the plugin without linking it
```

`cmu_add_executable()` comes with Nebula, from CMakeUtils: it finds the sources of `src/`, and runs `windeployqt` after
each build, which copies Qt next to the executable. The DLLs of Nebula are copied by the command after it.

Build it as the plugin, then run `Acme/build/bin/Release/Clock.exe`:

```text
Acme/build/bin/Release/
├── Clock.exe
├── Core.dll, Application.dll
├── Qt6Core.dll, Qt6Widgets.dll, ... and the plugins of Qt, platforms/, styles/...
├── plugins/TimePlugin.nbdl
└── scene/Clock.nbp
```

A project that uses the [standard plugins](Using-the-Standard-Plugins.md) needs `StandardPlugin.nbdl` in `plugins/`
as well: copy it from `NebulaStudio/Release/bin/plugins/` of the zip.

## Its options

`NebulaApplication` adds its options to those the `main` declared in the parser, then processes the command line: the
`main` reads its own options and arguments from the same parser afterwards. `--help` and `--version` come with them.

| Option | What it does |
| --- | --- |
| `--plugin-dir <directory>` | Lists the plugins of that directory too, after those of `plugins/`; as many times as needed |
| `--plugin-root <directory>` | The directory the plugin files of the project are relative to: the one of the executable otherwise |
| `--galaxy-dir <directory>` | Looks for the galaxy there first, before `scene/`; as many times as needed |
| `--log-level <level>` | The least severe messages written: `debug`, `info`, `warning`, `critical` or `fatal` |
| `--console` | Writes the messages to the error output, the terminal it is started from |
| `--log-file <file>` | Adds the messages to a file as well |

The code gives the same, and more, with a `Nebula::ApplicationOptions`: the command line comes on top of it.

```cpp
#include "Clock_info.h" // Generated by CMakeUtils for the executable Clock

Nebula::NebulaApplication app(argc, argv, parser, QStringLiteral("Clock.nbp"),
                              {.pluginDirectories = {QStringLiteral("extensions")},
                               .executable = {.name = QString::fromUtf8(ClockInfo::name),
                                              .version = QString::fromUtf8(ClockInfo::version),
                                              .organization = QString::fromUtf8(ClockInfo::organization)},
                               .logLevel = QtInfoMsg});
```

`Clock_info.h` holds what CMake knows of the executable: its `name`, the `version` of the project, and the
`organization`, `cmu_organization`. `Clock --version` then prints `Clock 1.0.0`.

`executable` is what the executable tells of itself: the version that `--version` shows, and its organization and name,
which name the directory its [settings files](Settings-Files.md) are written to by default. Set them before you
deliver: changed afterwards, the users lose what they chose. A relative path is read from the directory of the
executable in the code, and from the current directory on the command line. The
[README](https://github.com/Shuko83/Nebula/blob/main/README.md) lists every option of `ApplicationOptions`.

## See its messages

An application on Windows has no console of its own: its messages, and those of Nebula and Qt, go nowhere you can see.

```bash
Clock --console --log-level debug
```

writes them to the terminal it is started from, and `--log-file clock.log` to a file. `logger`, in
`ApplicationOptions`, is a function they are given to as well, to show them in a window say. Messages of Nebula are in
the categories `nebula.application`, `nebula.plugins`, `nebula.components` and `nebula.settings`; a
[`LogComponent`](Using-the-Standard-Plugins.md#write-to-the-log) in the galaxy writes those of your components, and
filters them all while it runs.

## When it does not run

`exec()` returns at once, with the reason logged as a critical message and in `errorString()`:

| Code | Means | For example |
| --- | --- | --- |
| `NebulaApplication::LoadFailed` (1) | The galaxy cannot be found, or all of it cannot be loaded | `The galaxy Clock.nbp is in none of C:\...\scene` |
| `NebulaApplication::StartFailed` (2) | An instance refused to start | |

Opening is strict: a plugin missing, an instance that cannot be created, a binding that cannot be made, and nothing
runs. Start it with `--console` to read why, or open the project in NebulaStudio, which tells what it could not
restore. See [troubleshooting](Troubleshooting.md#an-application-ends-at-once).

## Reach its instances

`app.universe()` is the `Nebula::Universe` it runs: `app.universe().component(QStringLiteral("Clock1"))` reaches an
instance by its name, before `exec()` say. `isLoaded()` and `galaxyFile()` tell the rest. There is one
`NebulaApplication` at a time, as there is one `QApplication`.

An application that has its own `QApplication` uses a `Nebula::Universe` directly: `open()` the project, `start()` it,
then run its event loop. See the [README](https://github.com/Shuko83/Nebula/blob/main/README.md#the-universe-of-an-application).
